# Production-like deployment (VPS, k3s)

The same three charts as local; only Helm values differ (`values-prod.yaml` plus a few `--set` flags derived from
`.env.prod`). No chart template changes for production.

## What changes between local and VPS
| Concern | Local (k3d) | VPS (k3s) | Where |
|---|---|---|---|
| Hosts | `*.localhost` | `shop/dashboard/gateway.<ip-dashed>.sslip.io` | Makefile from `VPS_IP` |
| TLS | none | cert-manager + Let's Encrypt HTTP-01 through Traefik (`shop-tls`, `dashboard-tls`, `gateway-tls`) | `values-prod.yaml`, `deploy/k3s/cluster-issuers.yaml` |
| Secrets | generated by the charts | created once by `scripts/prod-secrets.sh`, referenced via `existingSecret` | `make prod-secrets` |
| Images | `wmg/<svc>` imported into k3d | `ghcr.io/<owner>/wmg-<svc>:<short sha>` (amd64 + arm64) | `.github/workflows/release.yml` |
| Storage | `local-path`, 2 Gi | `local-path`, 10 Gi store, 5 Gi Postgres | `values-prod.yaml` |
| Gateway | 1 replica | 2 replicas + PodDisruptionBudget, `Secure` cookies | `values-prod.yaml` |
| Kubernetes API egress | k3d node IP | VPS node IP (detected at deploy time) | Makefile |

## Host: Oracle Cloud Always Free
One `VM.Standard.A1.Flex` (Ampere arm64, 4 OCPU / 24 GB), Ubuntu 24.04, 100 GB boot volume, in a VCN with one
public subnet. The cloud firewall (security list) opens **22 only from the operator's IP**, and 80/443 to everyone.
The Kubernetes API (6443) is never public; `kubectl` goes through an SSH tunnel.

Cost guard (set up first, from the OCI CLI):
- a quota policy that caps the tenancy at the Always Free amounts (A1 4 OCPU / 24 GB, 200 GB block storage) and
  zeroes backups, load balancers and databases;
- a monthly budget of 1 with email alerts on any actual spend and on forecast spend.

Expect "Out of host capacity" for A1 in some regions; retrying the launch every minute usually succeeds.

## Steps
```bash
cp .env.prod.example .env.prod      # VPS_IP, GH_OWNER, GEMINI_API_KEY (optional)
```
1. **Images.** Push the commit, then run the `release` workflow (Actions → release → Run workflow, or push a `v*`
   tag). It pushes `ghcr.io/<owner>/wmg-{gateway,dashboard,woo-mcp,mcp-gst,mcp-pincode}:<short sha>`. Make the five
   packages **public** once (GitHub → Packages → Package settings → Change visibility), so the cluster needs no
   pull secret.
2. **Bootstrap the VPS** (firewall, k3s, kubeconfig at `~/.kube/wmg-vps.yaml`, SSH tunnel, cert-manager,
   ClusterIssuers):
   ```bash
   make vps-bootstrap
   ```
   Oracle's Ubuntu image rejects all inbound traffic except SSH and all forwarded traffic in iptables; the script
   allows 80/443 and pod/service traffic, removes the FORWARD reject and saves the rules before k3s starts.
3. **Deploy**, first with the staging issuer (untrusted certificates, no rate limits):
   ```bash
   make prod-up CERT_ISSUER=letsencrypt-staging
   ```
   This runs `prod-secrets`, `prod-acme-netpol` (lets Traefik reach cert-manager's solver pods in our default-deny
   namespaces), `upstreams`, `store`, `seed-credentials` and `platform`, all with `ENV=prod`.
4. Check the certificates are issued (`KUBECONFIG=~/.kube/wmg-vps.yaml kubectl get certificate -A`), then switch to
   trusted certificates:
   ```bash
   make prod-up
   ```
5. **Sign in.** Dashboard admin password:
   `KUBECONFIG=~/.kube/wmg-vps.yaml make admin-password`.

## Test the deployment
```bash
KUBECONFIG=~/.kube/wmg-vps.yaml E2E_SCHEME=https E2E_DOMAIN=<ip-dashed>.sslip.io make e2e
```
Runs the acceptance and isolation suite against the VPS over HTTPS. Chat tests need a Gemini key with credit.

## Day 2
| Task | Command |
|---|---|
| Reopen the API tunnel after a reboot or sleep | `make vps-tunnel` |
| Shell on the VPS | `make vps-ssh` |
| Upgrade | push, run `release`, then `make prod-up` (deploys the current commit's short sha, or `IMAGE_TAG=<sha>`) |
| Roll back | `KUBECONFIG=~/.kube/wmg-vps.yaml helm rollback <release> <revision> -n <namespace>` |
| Rotate the LLM key | edit `.env.prod`, `make prod-secrets`, restart `deploy/platform-gateway` |
